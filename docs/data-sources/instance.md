# lima_instance (Data Source)

Reads an existing Lima instance. This data source never modifies the instance.

`name` is the **real** Lima instance name and is **not** affected by the
provider's `name_prefix`, so it can read instances Terraform does not manage.

## Example usage

```hcl
data "lima_instance" "default" {
  name = "default"
}

output "default_status" {
  value = data.lima_instance.default.status
}

output "ssh_command" {
  value = "ssh -F ${data.lima_instance.default.ssh_config} ${data.lima_instance.default.hostname}"
}
```

Reading an instance managed elsewhere in the same configuration:

```hcl
data "lima_instance" "managed" {
  name = lima_instance.dev.instance_name
}
```

## Schema

### Required

- `name` (String) The Lima instance name to look up, exactly as `limactl list` reports it.

### Optional

- `timeouts` (Attributes) (see [below for nested schema](#nestedatt--timeouts))

### Read-Only

- `arch` (String) Machine architecture, for example `aarch64`.
- `cpus` (Number) Number of virtual CPUs.
- `dir` (String) The instance directory inside `LIMA_HOME`.
- `disk` (String) Primary disk size in IEC notation, for example `100GiB`.
- `hostname` (String) Guest hostname, normally `lima-<name>`.
- `lima_version` (String) The Lima version recorded against this instance, falling back to the detected host version.
- `memory` (String) Memory size in IEC notation, for example `4GiB`.
- `protected` (Boolean) Whether Lima's deletion protection is enabled for this instance.
- `raw_status` (String) The status exactly as Lima reported it, for example `Running`.
- `ssh_address` (String) Host address for SSH. For a stopped instance this is the last known value, not a live endpoint.
- `ssh_config` (String) Path to the SSH configuration file Lima generates for this instance. No key material is exposed.
- `ssh_port` (Number) Host port forwarded to guest SSH. For a stopped instance this is the last known value.
- `ssh_user` (String) Guest login name from Lima's resolved configuration.
- `status` (String) Normalised status: one of `running`, `stopped`, `creating`, `broken` or `unknown`. A Lima status the provider does not recognise maps to `unknown`, with the original preserved in `raw_status`.
- `vm_type` (String) VM backend, for example `vz` or `qemu`.

## Notes

**On a stopped instance, `ssh_address` and `ssh_port` are last-known values,
not a live endpoint.** Lima continues to report them after a stop.

If the instance does not exist, the data source fails with an error naming the
`LIMA_HOME` that was searched and suggesting `limactl list`. Use the
`lima_host` data source's `instance_names` attribute if you need to check for
existence without failing.
