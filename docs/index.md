# Lima Provider

Manages local [Lima](https://lima-vm.io/) virtual machines declaratively.

> This provider orchestrates Lima through the supported `limactl` lifecycle.
> It does not replace Lima or manage Lima's internal files directly.

> **Unofficial.** Not affiliated with, endorsed by, or supported by the Lima
> project or HashiCorp.

> **Pre-1.0.** This provider is in its `0.x` line, where a **minor** bump may
> change the schema in a breaking way — including changes that require
> `terraform state` surgery rather than only an edit to a `.tf` file. Terraform
> does not special-case `0.x`, so `~> 0.1` would upgrade you across such a
> change: pin the patch range with `~> 0.1.0` as shown below. Every breaking
> change is listed in the
> [changelog](https://github.com/guidoiaquinti/terraform-provider-lima/blob/main/CHANGELOG.md)
> with its migration steps.

## Example usage

```hcl
terraform {
  required_providers {
    lima = {
      source  = "guidoiaquinti/lima"
      version = "~> 0.1.0"
    }
  }
}

provider "lima" {
  # Every attribute is optional; this block can be empty.
}

resource "lima_instance" "dev" {
  name     = "project-dev"
  template = "template:ubuntu"

  cpus   = 4
  memory = "8GiB"
  disk   = "50GiB"
}
```

### Isolated Lima home

```hcl
provider "lima" {
  home        = "~/.lima-terraform"
  name_prefix = "tf-"

  default_timeout = "30m"
}
```

## Requirements

`limactl` must be installed and on `PATH` on the machine that runs
`terraform apply`. The provider verifies this during configuration and runs a
version check, so a missing or unusable Lima produces an actionable error
before any resource is touched.

Because the provider shells out to a local binary, it cannot run in a remote
execution environment that lacks Lima.

## Schema

### Optional

- `binary` (String) Path to the `limactl` executable. Defaults to `limactl` resolved from `PATH`. May also be set with the `LIMA_PROVIDER_BINARY` environment variable. The provider verifies that the file exists and is executable, and runs a version check, during configuration.
- `default_timeout` (String) Overrides the timeout of every operation that does not set its own, as a Go duration such as `20m` or `1h30m`. When unset, each operation uses its own default: `30m0s` to create, `20m0s` to update, `20m0s` to delete and `2m0s` to read. Setting this applies the same value to all four, so keep in mind that it raises the budget for a refresh as well as for a slow VM creation. May also be set with the `LIMA_PROVIDER_DEFAULT_TIMEOUT` environment variable.
- `environment` (Map of String) Additional environment variables for every `limactl` invocation. These are merged over the inherited process environment and take precedence on conflict, including over `home`. Values are never written to logs or diagnostics.
- `home` (String) Value to pass to Lima as `LIMA_HOME`. May also be set with the `LIMA_HOME` environment variable. A leading `~` is expanded and the path is normalised. The provider never creates or removes this directory itself; only Lima does. When unset, Lima's own default (`~/.lima`) applies.
- `name_prefix` (String) Prefix applied to the `name` of every managed instance to form the real Lima instance name. Defaults to an empty string. May also be set with the `LIMA_PROVIDER_NAME_PREFIX` environment variable. Import IDs are always the **real** Lima instance name, prefix included; see the `lima_instance` resource documentation for details.

## Supported Lima versions

**Lima 2.0 or newer is required.** The 1.x line is not supported.

| Provider version | Lima version | Behaviour                                                 |
| ---------------- | ------------ | --------------------------------------------------------- |
| 0.1.x            | 2.2.0        | Developed and verified against Lima 2.2.0, macOS 15 arm64. |
| 0.1.x            | 2.0 – 2.1    | Accepted, not exercised. 2.0 is the enforced minimum.      |
| 0.1.x            | > 2.2.0      | Accepted with a warning.                                   |
| 0.1.x            | < 2.0        | **Rejected** at provider configuration time.               |

An older-than-minimum Lima is an **error**. A newer-than-tested Lima is a
**warning** only, so upgrading Lima cannot break a working configuration.

## Logging

The provider uses Terraform's plugin logging. Enable it with:

```console
$ TF_LOG=DEBUG terraform apply
```

Debug logs include the command name and redacted arguments, state transitions,
polling summaries, version detection and sanitised Lima stderr on failure.

They never include private keys, provisioning script bodies, sensitive YAML
values or environment secrets.
